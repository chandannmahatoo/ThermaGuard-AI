# ThermaGuard AI frontend verification

Verified locally on 12 September 2026. No commit or push was performed. Backend APIs, model artifacts, deterministic risk logic and tracked data were not modified.

1. **Files modified.** `frontend/app/page.tsx`, `frontend/app/globals.css`, `frontend/lib/api.ts`; existing components `AlertCenter`, `AnalyticsView`, `ContextPanel`, `CopilotModal`, `EventDetailDrawer`, `EventTable`, `FilterToolbar`, `LandingPage`, `MapView`, `NotificationSettings`, `OverviewKPIs`, `ProviderHealthGrid`, `ReviewCenter`, and `StatusBadge`; existing tests `dashboard.test.mjs` and `providers.test.mjs`. New files: `frontend/components/ContextCoverage.tsx`, `frontend/components/OperationalSummary.tsx`, `frontend/lib/useDialogFocus.ts`, `frontend/tests/experience.test.mjs`, and this report.
2. **Components.** Reused the existing page architecture and component library. Added shared seven-source context coverage, a recorded operational activity summary, and modal focus containment/restoration.
3. **Landing, login and signup.** Retained the polished public landing and actual `/auth/register` contract. Verified sign-in, authenticated workspace entry, logout and registration form rendering. Authentication loading hides protected content. Password visibility is keyboard accessible. No account was created during browser verification. Registration and dashboard remain views at `/`, rather than separate deep links.
4. **Dashboard.** Exact requested nine-item navigation, collapsible desktop sidebar and mobile menu. Eight KPI cards now distinguish monitored stored events from an unsupported active-event lifecycle. Added High risk, detection and reviewed-candidate counts. Missing event/provider data is unavailable rather than a fabricated zero/configuration claim. Operational state uses health, FIRMS, model and provider responses. Recent activity uses recorded timestamps only.
5. **Map.** Canvas rendering for observation volume; graduated event markers, cross-sensor rings, selected halo, raw FIRMS, optional industrial/EONET/satellite context and actual route geometry. Subscriber radius uses Leaflet geographic Circle in meters, accepts zero coordinates, and is no longer a pixel approximation. Selection preserves viewport; explicit zoom, clear, reopen-detail and view-on-map actions are available. Industrial and satellite overlays identify event-context positions, not invented infrastructure geometry.
6. **Event explorer.** Classification and candidate-review filters complement risk, sensor, observation-window, context, EONET, search and geographic filters. Removable filter chips and reset. Verified cross-sensor filtering in the live browser. Existing sorting/pagination retained; sorting headers support keyboard activation. First-seen and review columns added. Candidate annotations are read-only export claims, not new model labels or approvals.
7. **Event drawer.** Eleven separate sections: Overview, Thermal Evidence, Location, Weather, Air Quality, Satellite, Industrial Context, Natural Hazards, Routing, AI Copilot and Raw Evidence. Shared coverage, coordinate copying and context provenance. Corrected collapsed tab layout and unsupported model-confidence/version claims. Negative EONET match wording requires an available response explicitly reporting `matched: false`; deferred/failed evidence remains distinct.
8. **Provider telemetry.** Eleven provider cards. Missing registry entries show Unavailable. Configuration is not presented as a successful interaction. Cards display backend status, interaction history, latency and safe error categories where supplied. Added Blocked badge and explanations of state semantics. No synchronous provider probes or credential display.
9. **Alerts.** Existing severity/status filters plus recorded delivery-channel and creation-date filters. Actual acknowledgments and email/push audit states retained. Empty delivery history is explicit. Recipient radius is not fabricated when absent from the alert response. Acknowledgment and delivery actions were not triggered during browser checks.
10. **Copilot.** Submission requires one selected event in both page and modal. Changing events clears prior answers; stale requests cannot attach answers to a new selection. Suggestions remain event-specific. Backend Gemini/fallback output preserved. Escape closes Copilot without also closing the underlying drawer. No direct cloud-model request from the frontend.
11. **Analytics.** Preserved real trends, risk, classification, sensors and context distributions. Added reviewed-candidate, recorded delivery and provider-state summaries. Empty historical series does not generate substitute observations.
12. **Notifications.** Null coordinates normalize to controlled empty strings; absent radius uses 10 km. Coordinate ranges and required location are checked before enabling. Existing saved values are preserved. Current GPS remains an explicit user action. Unsupported independent channel/critical-only settings and missing device-status telemetry are explained instead of silently stored. Threshold updates require an explicit new value, rather than prepopulating an unverified current threshold.
13. **Responsive behavior.** Tested at 390 × 844 and desktop dimensions. Mobile event rows become cards, the drawer becomes a bottom sheet and Copilot fills the viewport. Fixed sidebar, top-bar and footer overflow; measured document width equaled the 390 px viewport. Reset the temporary viewport override afterward.
14. **Accessibility.** Modal focus trapping/restoration, Escape handling, navigation `aria-current`/expanded state, keyboard sorting/password controls, visible focus, labeled inputs and non-color risk labels. Reduced-motion CSS disables animations/transitions. Hidden mobile navigation is removed from visible keyboard interaction.
15. **React warnings.** No React warnings or console errors observed in the tested browser session. This is an observation of exercised flows, not a guarantee for every future provider response.
16. **Frontend tests.** `npm --prefix frontend test`: **51 passed, 0 failed**. Preserved existing coverage and added 18 tests covering public/auth loading, unavailable/blocked telemetry, coverage, successful negative EONET context, routing, geographic radius, eleven drawer sections, controlled notification defaults, alert filters, unselected Copilot, unavailable KPIs and empty analytics/activity.
17. **Typecheck.** `npm --prefix frontend run typecheck`: **passed**.
18. **Production build.** `npm --prefix frontend run build`: **passed**. Next.js 15.5.25 compiled and prerendered successfully. The `/` route reports approximately 251 kB first-load JS. A local scan of 17 production JavaScript bundles found none of the configured backend secret values. No standalone lint script is defined.
19. **Backend regression.** `PYTHONPATH=backend ./.venv/bin/pytest backend/tests -q`: **331 passed**, with five existing SDK/Python deprecation warnings. `./.venv/bin/python -m compileall backend`: **passed**. `git diff -- backend models data` was empty; no model training, synchronization, notification delivery, label finalization or database mutation was requested by this frontend work.
20. **Browser verification.** Exercised landing, login, protected loading, Overview, Live Map, Events/filter/reset/selection, context drawer, Providers, Alerts, Analytics, Review & Labels, Settings, Copilot presentation, nested Escape behavior, mobile navigation/cards, logout and registration form. Backend runs on 127.0.0.1:8000 and frontend dev server on 127.0.0.1:3000. Production build was completed before restarting development mode.
21. **Remaining limitations.** Live cloud AI answers, email/push delivery, new-account creation and on-demand external route calculation were not triggered by browser verification; deterministic fallback and route-availability presentation were covered by tests. Provider registry configuration alone does not prove live health; OSM/Copernicus registry entries can be absent despite stored event context. Backend does not expose a V2-specific readiness response, per-user device-registration status, independent email/push/critical-only preferences, or recipient-radius details in alert records. Review candidates are admin-only snapshots and can differ from current event evidence. Observation-date filtering currently uses preset windows. URL deep links to individual app views are not implemented. These boundaries are shown honestly without changing backend contracts.
